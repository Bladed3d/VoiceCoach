This allows you to:

Capture the user's microphone (your side of the conversation) using navigator.mediaDevices.getUserMedia.
Capture the system/tab audio (the remote participant's side) using navigator.mediaDevices.getDisplayMedia with options to grab the current tab's audio output. This works well for web-based video calls because the remote audio is playing through the browser tab.

This setup assumes you're building an Electron desktop app that embeds the video call (e.g., via a <webview> or by loading the URL in the main window). The captured audio streams can then be processed in real-time—e.g., recorded, mixed, or piped to a speech-to-text engine like Vosk (which has JavaScript bindings via vosk-browser or a custom worker) or sent to your Python backend (e.g., via IPC or WebSockets for transcription with Faster-Whisper).
Important Notes Before Code

Permissions: Electron/Chromium will prompt the user for microphone and screen-sharing permissions. For tab audio, use preferCurrentTab: true to avoid capturing the entire screen.
Audio Only: We'll focus on audio capture (set video: false in getDisplayMedia for efficiency).
Mixing Streams: If you need a single combined audio stream (both sides), use AudioContext to merge them.
Vosk Integration: If you're using Vosk for real-time STT, install vosk-browser (a WebAssembly port) via npm. I'll include a stub for it.
Limitations:

System audio capture requires the video call to be in the same Electron window or a captured tab.
On some OSes (e.g., macOS), you might need additional setup for loopback audio (e.g., install BlackHole or Loopback virtual audio drivers).
This won't capture encrypted audio (e.g., DRM-protected YouTube videos), but it works for standard video calls.


Dependencies: Install via npm: electron, vosk-browser (optional for JS-based STT).
Testing: Run on a platform where you can join a test call (e.g., Google Meet test room).
Python Integration: If you want to send audio to your Python app (e.g., for Whisper), use Electron's IPC to communicate with a Node.js child process or a local server.

This is where the magic happens. Attach it to your index.html (see below).
javascript// Optional: Import Vosk for JS-based real-time STT
// const Vosk = require('vosk-browser');  // Uncomment if using Vosk

// Function to start capturing both sides
async function startAudioCapture() {
  try {
    // Step 1: Capture microphone (user's side)
    const micStream = await navigator.mediaDevices.getUserMedia({
      audio: true,
      video: false,
    });
    console.log('Microphone captured.');

    // Step 2: Capture tab/system audio (remote side)
    // Use getDisplayMedia with preferCurrentTab for the current browser tab audio
    const tabStream = await navigator.mediaDevices.getDisplayMedia({
      audio: {  // Capture audio only
        echoCancellation: false,  // Important for clear remote audio
      },
      video: false,  // Set to true if you also want video
      preferCurrentTab: true,  // Captures the current tab (e.g., Meet/YouTube)
    });
    console.log('Tab audio captured.');

    // Step 3: Process the streams (e.g., record, transcribe, or mix)
    // Option A: Mix both streams into one (for combined transcription)
    const audioContext = new AudioContext();
    const micSource = audioContext.createMediaStreamSource(micStream);
    const tabSource = audioContext.createMediaStreamSource(tabStream);
    const destination = audioContext.createMediaStreamDestination();
    micSource.connect(destination);
    tabSource.connect(destination);
    const combinedStream = destination.stream;
    console.log('Streams mixed.');

    // Option B: Process separately (e.g., transcribe each side independently)
    // processStream(micStream, 'User');  // Your side
    // processStream(tabStream, 'Remote');  // Remote side

    // Example: Record the combined stream (save to file or pipe to STT)
    const mediaRecorder = new MediaRecorder(combinedStream, { mimeType: 'audio/webm' });
    mediaRecorder.ondataavailable = (event) => {
      if (event.data.size > 0) {
        // Send blob to Python via IPC or WebSocket for Whisper transcription
        // Or process in JS with Vosk (see below)
        console.log('Audio chunk available:', event.data);
      }
    };
    mediaRecorder.start(1000);  // Chunk every 1s for real-time

    // Optional: Real-time STT with Vosk in JS
    // await initVoskSTT(combinedStream);  // See function below

  } catch (error) {
    console.error('Error capturing audio:', error);
  }
}

// Optional: Function to initialize Vosk for real-time STT on a stream
async function initVoskSTT(stream) {
  // Assuming vosk-browser is installed
  const Vosk = require('vosk-browser');
  const modelPath = 'path/to/vosk-model';  // Download from Vosk site and load

  const recognizer = new Vosk.Recognizer({
    model: await Vosk.createModel(modelPath),
    sampleRate: 16000,  // Match your sample rate
  });

  const audioContext = new AudioContext({ sampleRate: 16000 });
  const source = audioContext.createMediaStreamSource(stream);
  const processor = audioContext.createScriptProcessor(4096, 1, 1);

  source.connect(processor);
  processor.connect(audioContext.destination);

  processor.onaudioprocess = (event) => {
    const inputBuffer = event.inputBuffer.getChannelData(0);
    if (recognizer.acceptWaveform(inputBuffer)) {
      const result = recognizer.result();
      console.log('Vosk Transcription:', result.text);
      // Send to main process: window.ipcRenderer.send('transcription-update', result.text);
    }
  };
}

  tabStream?.getTracks().forEach(track => track.stop());
}

Troubleshooting

No Tab Audio: Ensure the video call is active in the captured tab. If on macOS/Windows, test with virtual audio drivers for full system loopback.
Echo: Disable echo cancellation if mixing streams.
Performance: Downsample audio to 16kHz for Vosk/Whisper.
Python Bridge: If sending to Python, use node-fetch or WebSockets in renderer.js to POST audio blobs to a local Flask/FastAPI server running your transcription pipeline.
